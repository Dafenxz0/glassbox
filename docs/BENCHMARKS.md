# GlassBox Benchmarks & Verification Ledger

All metrics below are measured directly from `studio/demo-data/benchmarks_summary.json` (generated by [`scripts/generate_demo_artifacts.py`](../scripts/generate_demo_artifacts.py)) on Windows x86_64 CPU. No numbers are estimated or extrapolated.

## Benchmark Methodology

Measured via `glassbox.benchmark.run_benchmarks`:
- **Latency & throughput**: `n_warmup = 100` warmup iterations followed by `n_iters = 2000` single-sample (`batch = 1`) evaluations timed with `time.perf_counter_ns()`.
- **Numerical fidelity (`max_diff_vs_ref`)**: Verified across 200 deterministic domain points.
  - `ONNX Runtime (CPU)` (`onnxruntime.InferenceSession`, `CPUExecutionProvider`) and `PyTorch (Eager CPU)` (reconstructed `nn.Sequential`) are compared against `LoadedModel.predict`.
  - `Decompiled Python (Zero-Dep)` and `Decompiled C99 (Native DLL)` are compared against `DecompiledProgram.predict`.
- **Native C99 compilation**: Emitted C99 source is compiled with `ziglang cc -O3 -shared -std=c99` and invoked per sample via `ctypes`. Reported C99 DLL latency (`0.50–0.70 us`) therefore includes Python `ctypes` FFI call overhead; artifact bytes reflect the compiled shared library binary.

```bash
# Or benchmark an individual model + IR pair via CLI
glassbox bench models/drone_altitude_pid.onnx /tmp/gb_out/drone_altitude_pid.ir.json
```
